About This Project

How EcoSort AI is built, and why it's designed this way.

The Problem

Improper waste segregation at source is one of the biggest obstacles to effective recycling and composting. Most households and institutions mix biodegradable, recyclable, e-waste and hazardous items into a single bin, making downstream sorting expensive, unsafe and often impossible. EcoSort AI demonstrates how computer vision can guide correct segregation at the point of disposal, in real time.

How It Works — Technical Pipeline

  1. Capture: The browser grabs frames from the webcam (or an uploaded photo) using the HTML5 Media/Canvas APIs — entirely client-side.
  2. Detection: Each frame is sent to a local Flask endpoint, which runs it through a YOLOv8 object-detection model (Ultralytics, pretrained on the COCO dataset — 80 everyday object classes), returning bounding boxes, class labels and confidence scores for every object found. This is the multi-object detection stage.
  3. Classification: A rule-based reasoning engine (waste_map.py) maps each detected object class to one of five waste-segregation categories — Biodegradable, Recyclable, Non-Recyclable, E-Waste or Hazardous — using a curated lookup table grounded in real municipal solid-waste guidelines.
  4. Guidance: The matched category's disposal tip is displayed on-screen and read aloud via the Web Speech API, and the detection is logged to a local SQLite database for the dashboard, streaks and eco-points.

Why Pretrained Detection Instead of Training From Zero?

A custom model trained on a small, student-collected image set is fragile — lighting, background clutter and unseen objects on the exam day can easily break it. EcoSort AI instead uses a robust, industry-grade, pretrained detector for perception, and puts the project's original engineering into the classification and reasoning layer on top — the same "detect, then reason" architecture used in real-world recycling-robot systems (e.g. AI-guided material recovery facilities). This keeps live demos reliable while still requiring genuine design decisions: category mapping, confidence thresholds, gamification logic and the offline chatbot.

Tech Stack

Backend

Python, Flask, SQLite

Computer Vision

Ultralytics YOLOv8 (PyTorch), OpenCV, Pillow

Frontend

HTML5, CSS3, vanilla JavaScript, Chart.js

Extras

Web Speech API (voice), difflib-based chatbot, localtunnel for public demo access

Deployment & Control

The entire application runs on the student's own machine via python app.py inside VS Code — no Google Colab, no third-party AI API, no external hosting. When a public link is needed for a demo, it is created on-demand with the student's own localtunnel session, which can be started and stopped at will, keeping the server fully under the developer's control at all times.
